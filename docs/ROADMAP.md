# Roadmap

## Phase 01 — Foundation

Versioned JSON metadata, lifecycle gates, provenance/unknown handling, governance,
deterministic validation, and least-privilege GitHub review workflows. No market
or scientific result is claimed by this phase.

## Phase 02 — Proposed only; not authorized or implemented

1. Agree with the researcher on public GitHub domains, candidate budget, inclusion
   criteria, research questions, and permitted read-only discovery access.
2. Design a human-reviewed candidate rubric: relevance, mathematical clarity,
   license, maintenance, tests, reproducibility, data requirements, and security.
3. Collect a small set of public candidate metadata with source URLs and capture
   timestamps; pin SHAs only when actually resolved. Keep missing values UNKNOWN.
4. Register candidates as DISCOVERED without executing or cloning their code.
5. Select a pilot via human review; inspect source at a pinned SHA and license.
   Document competing mechanisms, assumptions, asset-transfer limits, and tests.
6. Propose a separately approved reproduction plan with commands, dependencies,
   resource limits, public/synthetic data, rights, expected artifacts, and falsifiers.

Acceptance: traceable shortlist and one reviewable mechanism/reproduction proposal,
not a profitable strategy or validated market claim. Do not implement scraping,
automated acquisition/execution, RAG, or market feeds under the Phase 01 task.
